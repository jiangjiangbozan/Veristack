# Evidence Pack 格式契约（版本 1）

Evidence Pack 是一份可以脱离 Veristack 服务端独立核验的交付证据快照。客户或第三方拿到 Pack 后，无需信任服务端，也能确认交付内容是否被篡改。

本契约独立版本化，未来允许其他实现产出兼容的 Pack。

## 一、目录结构

```
<pack-root>/
├── pack.json          # 元数据：清单摘要、证据清单与签名
├── manifest.json      # 交付清单快照，与交付创建时冻结的内容一致
└── files/             # 证据附件，文件名即内容摘要
    ├── <sha256>.png
    └── <sha256>.xml
```

## 二、pack.json

```json
{
  "schemaVersion": "1",
  "generatedAt": "2026-11-25T10:00:00+08:00",
  "delivery": {
    "baselineVersion": 2,
    "buildNo": "b-202",
    "gitRef": "abc1234",
    "id": "78951c02-3178-4763-b061-2fd16dab996f",
    "projectName": "官网改版",
    "version": 1
  },
  "manifestSha256": "a08b27008e6aaae126aa15b880923052f7a0bc43eef5e2cc215dd7e11a37f5c4",
  "files": [
    {
      "evidenceId": "6f1c...",
      "path": "files/8d3a....png",
      "sha256": "8d3a...",
      "size": 20480,
      "title": "首页深色模式截图"
    }
  ],
  "signature": {
    "algorithm": "ed25519",
    "publicKey": "BASE64",
    "value": "BASE64"
  }
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schemaVersion` | string | 是 | 格式版本，当前为 `1` |
| `generatedAt` | string | 是 | 生成时间，上海时区 |
| `delivery` | object | 是 | 交付版本基本信息 |
| `manifestSha256` | string | 是 | `manifest.json` 的 SHA-256 摘要（十六进制小写） |
| `files` | array | 是 | 证据附件清单 |
| `signature` | object | 否 | 清单签名，未配置签名私钥时为空 |

### 文件条目

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `evidenceId` | string | 证据 ID，便于回溯服务端记录 |
| `path` | string | Pack 内相对路径，使用正斜杠分隔 |
| `sha256` | string | 文件内容摘要 |
| `size` | number | 文件字节数 |
| `title` | string | 证据标题 |

## 三、manifest.json

内容与交付版本创建时冻结的交付清单完全一致，是不可覆盖的快照。典型结构：

```json
{
  "baselineVersion": 2,
  "criteria": [
    {
      "description": "首页加载小于 2 秒",
      "key": "REQ-001::0",
      "requirementCode": "REQ-001"
    }
  ],
  "gitRef": "abc1234",
  "projectName": "官网改版",
  "requirements": [
    {
      "code": "REQ-001",
      "criteria": [{ "description": "首页加载小于 2 秒", "key": "REQ-001::0", "requirementCode": "REQ-001" }],
      "description": "首页需支持主题切换",
      "priority": "high",
      "title": "首页主题"
    }
  ],
  "version": 1
}
```

验收条件的 `key` 是稳定标识，格式为 `需求编号::序号`，客户逐条验收的裁定结果通过该键关联。

## 四、签名

签名算法为 Ed25519，签名对象是 `manifestSha256` 的原始字节串。

- 服务端持有私钥，导出 Pack 时对 `manifestSha256` 签名
- 公钥随 Pack 一起分发，客户据此验证
- 私钥只保存在服务端，丢失后无法为历史 Pack 补签

校验规则：

1. `signature.algorithm` 必须为 `ed25519`
2. `publicKey` 解码后长度必须为 32 字节
3. `value` 解码后必须是对 `manifestSha256` 的有效签名
4. 文件实际摘要必须等于 `manifestSha256`

第 4 条保证「签名覆盖的正是客户看到的内容」，而非仅证明某个摘要被签过名。

## 五、核验流程

使用官方 CLI：

```bash
veristack verify ./delivery-pack
```

输出示例：

```
交付：官网改版 v1（基线 v2）
清单摘要：a08b27008e6aaae1...

[通过] 交付清单摘要：清单内容与元数据一致
[通过] 证据附件 files/8d3a....png：附件内容与元数据一致
[通过] 交付清单签名：签名有效

结论：全部核验通过，交付内容与签名均有效
```

CLI 在任一核验项失败时返回非零退出码，便于接入流水线做自动卡口。

自行实现核验时，参考 `api/internal/platform/pack/verify.go`。

## 六、兼容性

- 新增字段属于向后兼容变更，`schemaVersion` 不变
- 删除或改变已有字段语义属于破坏性变更，必须提升 `schemaVersion` 主版本号
- `schemaVersion` 使用「主版本.次版本」形式，当前为 `1`
